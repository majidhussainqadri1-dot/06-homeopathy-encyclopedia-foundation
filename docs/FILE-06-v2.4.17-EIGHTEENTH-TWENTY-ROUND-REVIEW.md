# File 06 v2.4.17 — Eighteenth Fresh Twenty-Round Review

Repository-only corrective record. Staging/live/operational status is not established by this review.

1. **DEFECT** — The v2.4.16 relation command had moved to opaque reference tokens, but the earlier graph guard still absint-cast the token and rejected every valid request. The guard now decodes only the scope-bound reference token and rejects raw numeric identifiers.
2. **DEFECT** — The canonical public-translation route accepted a known concept UUID without enforcing approved/safe/published domain state or authoritative WordPress publish state. Public translations now require both governed eligibility and a published File 06 WordPress object.
3. **DEFECT** — The older Third-Audit meta hook mutated canonical concept language before the newer CAS/invalidation owner ran, allowing the stronger language-governance path to be bypassed. The stale pre-emptive meta hooks were removed; Language Surfaces is now the sole meta-to-domain synchronization owner.
4. **DEFECT** — A canonical source-language change did not advance row_version or invalidate prior review/safety approval, so semantically changed knowledge could remain approved under a stale review fingerprint. The language CAS now increments row_version, invalidates review/safety, reindexes and emits a governed change event.
5. **DEFECT** — Future-18 readiness trusted only its version option, so missing/corrupt Future tables or columns could be treated as ready. A concrete twelve-table shape check now gates upgrade, verification and migration readiness.
6. **DEFECT** — The Future schema installer wrote the core File 06 schema-version option, allowing a Future install to falsely assert core-schema currency. Future schema now updates only its own version; core schema truth remains owned by HE_V2_Schema.
7. **DEFECT** — Future maintenance scheduling ignored wp_schedule_event failure, so a candidate could appear healthy while freshness/retraction/impact maintenance never ran. Scheduling now requests WP_Error detail, records runtime failure and returns explicit success/failure.
8. **DEFECT** — Retraction Watch advanced its cursor and reported rows as checked even when the authoritative external-record update failed or provider processing stopped early. Persistence/provenance are now checked and the cursor advances only through successfully processed rows; checked reports actual work.
9. **DEFECT** — The maintenance worker ignored failure of the bulk translation-outdated write and then completed normally. The write is now checked, records a runtime failure, and terminates that maintenance pass on persistence failure.
10. **DEFECT** — Future health queried Future tables even when migration/schema shape was incomplete, which could emit WordPress DB errors and misleading zeros. Health now checks shape first, avoids missing-table queries and reports explicit degraded readiness/schedule state.
11. **DEFECT** — Claim-evidence insertion, claim review invalidation/row-version bump and provenance were separate writes; the claim update was unchecked. Evidence changes now require expected row_version and commit evidence + claim CAS + provenance atomically or roll back.
12. **DEFECT** — Future claim commands still exposed raw claim/concept/version row IDs. Claim review/evidence routes now use claim UUIDs, claim writes resolve canonical concept UUIDs, and version selection uses public version_number rather than a versions-table primary key.
13. **DEFECT** — Future claim evidence still accepted raw reference IDs and external staging accepted/returned internal object and external-record IDs. Evidence now consumes the opaque reference token; external binding takes canonical object UUIDs and response IDs are opaque/public.
14. **DEFECT** — Translation mutation routes exposed translation/concept row IDs and review/publish treated zero-row CAS updates as success. Commands now use canonical concept UUID + locale, and review/publish use transactional exact-state CAS with fail-closed stale-source/version handling.
15. **DEFECT** — Remaining concept-scoped Future mutations (impact, mapping and duplicate scan) still consumed internal concept IDs. They now resolve canonical concept UUIDs, including object-scope authorization and normalizer route matching.
16. **DEFECT** — Pristine composer rollback queried Future tables whenever the class was loaded, even if Future migration/schema was incomplete. Unknown Future child state now fails closed and rollback is denied without querying an unverified schema.
17. **DEFECT** — The public language filter advertised languages from domain rows whose authoritative WordPress entry was no longer public. Public-language discovery now requires the same published WordPress projection and current governed version as public knowledge.
18. **CLEAN** — Fresh authorization/IDOR, public DTO/privacy, migration/rollback and provider-degraded-path review of the corrected state found no additional actionable repository-level defect.
19. **DEFECT** — Corrective source changes left runtime, contract, stable tag and aggregate package/release truth at v2.4.16. Current candidate truth is aligned to v2.4.17; core DB schema remains 10 and Future internal schema remains 2.
20. **DEFECT** — Final exact-head WordPress route smoke exposed residual v2.3 numeric mutation routes plus stale v2.4.1/review-guard numeric object-scope patterns that could bypass canonical-ID reviewer/object gates. Legacy v2.3 REST/maintenance runtime is retired under v2.4+, external review now uses an opaque token, core integrity/research/dataset/external guards use current canonical IDs/tokens, and claim/translation reviewer-match indices are corrected; exact-head final QA must pass after this correction.
